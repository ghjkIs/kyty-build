NEW TEST: "uniform atomic descriptor phi" (TestUniformAtomicDescriptorPhi)
Models CS 0x1d81bb2b74faf456: uniform diamond on user data, lo/hi address
loads in each arm, hi Phi | 0x40000 flag, TWO GetBufferResource handles on the
same Phis each feeding an atomic (one in the merge block, one in a later block),
plus an unrelated straight-line StoreBufferU32 (a shape V2's sole-terminal-store
rule rejects).
Positive (run for BufferAtomicOr32 and BufferAtomicIAdd32):
- PlanAndTrack succeeds; GPU Phi / BitwiseOr32 SSA unchanged.
- Both atomic sites bind the SAME buffer, which is written+atomic+read; no
  IndirectBuffer fallback; program validates after DCE.
- Extracted resource plan evaluates to the correct base and keeps the 0x40000
  flag for both branch directions (user data 0 and 1).
Negative (must still fail with "not a valid runtime value"):
- 1: LaneId-dependent branch condition (also checks the opcode=BufferAtomicOr32
     diagnostic text is kept).
- 2: a buffer write before the diamond (host-read descriptor could be stale).
- 3: loop back-edge containing the atomics.
- 4: write-free loop around the diamond (atomics only after the loop).
Mutation checks: without V3 the new test fails with exactly the game's error
("unsupported GPU-selected access: opcode=BufferAtomicOr32 ..."); removing the
write-before check makes case 2 pass (test fails); removing the loop check
makes case 4 pass (test fails).
